# .NET Framework 4.6 packaging digest — round 1

- Strict .NET Framework 4.6 uses TFM `net46`. Its .NET Standard ceiling is 1.3; `netstandard2.0` begins at .NET Framework 4.6.1 and cannot satisfy the requirement. Sources: https://learn.microsoft.com/en-us/dotnet/core/tutorials/libraries#how-to-target-net-framework and https://learn.microsoft.com/en-us/dotnet/standard/net-standard (Microsoft; accessed 2026-08-28). Confidence: high. Class: version/compatibility.
- NuGet places managed assemblies under `lib/<tfm>` or compile-only references under `ref/<tfm>`, architecture-specific native assets under `runtimes`, and imported MSBuild logic under `build`. Source: https://learn.microsoft.com/en-us/nuget/create-packages/creating-a-package (Microsoft/NuGet; accessed 2026-08-28). Confidence: high. Class: packaging.
- Legacy `packages.config` projects do not reliably copy P/Invoke dependencies through managed reference resolution. Supporting older net46 project types requires explicit build targets/content copying or documented deployment. Sources: https://learn.microsoft.com/en-us/nuget/create-packages/select-assemblies-referenced-by-projects and https://learn.microsoft.com/en-us/nuget/guides/native-packages (Microsoft/NuGet; accessed 2026-08-28). Confidence: high. Class: packaging.
- An AnyCPU facade still runs at the host process bitness and must load a matching native DLL. Mismatch can produce `BadImageFormatException`. Sources: https://learn.microsoft.com/en-us/dotnet/csharp/language-reference/compiler-options/output#platformtarget and https://learn.microsoft.com/en-us/dotnet/api/system.badimageformatexception (Microsoft; accessed 2026-08-28). Confidence: high. Class: version/compatibility.
- Default Windows DLL search behavior can enable preloading attacks when searched directories are attacker-writable. The wrapper should securely load an absolute architecture-specific path or constrain DLL directories. Source: https://learn.microsoft.com/en-us/windows/win32/dlls/dynamic-link-library-search-order (Microsoft; accessed 2026-08-28). Confidence: high. Class: security.
- .NET Framework 4.6 retired on 2022-04-26. Supporting it is a legacy compatibility concession, not a supported modern baseline. Source: https://learn.microsoft.com/en-us/lifecycle/products/microsoft-net-framework (Microsoft; accessed 2026-08-28). Confidence: high. Class: lifecycle.
- CI can compile with `Microsoft.NETFramework.ReferenceAssemblies`, but runtime tests still need matching Windows x86/x64 processes. Source: https://learn.microsoft.com/en-us/dotnet/framework/migration-guide/reference-assemblies (Microsoft; accessed 2026-08-28). Confidence: high. Class: implementation.
- Full-framework projects may use `packages.config` or PackageReference, with limitations for some ASP.NET projects; both consumption models need tests. Source: https://learn.microsoft.com/en-us/nuget/consume-packages/package-references-in-project-files#project-type-support (Microsoft/NuGet; accessed 2026-08-28). Confidence: high. Class: consumer compatibility.

Recommendation: package an AnyCPU `lib/net46` facade with win-x86 and win-x64 native artifacts and conservative `build/net46` targets for legacy projects. Do not rely solely on RID-native selection until representative `packages.config` installations prove it works.
