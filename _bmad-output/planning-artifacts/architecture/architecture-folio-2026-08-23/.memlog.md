- (decision) PDF layer: Folio EMITS ITS OWN PDF (internal/pdf), rather than depending on a third-party writer. Forced by the stack above it — Folio does its own shaping (textshape), its own subsetting, and its own fixed-point layout, so it must place glyphs by GID via Identity-H TJ arrays and embed a subset font program it produced. gopdf owns font embedding internally and exposes no glyph-level draw API, so it cannot accept our subset; baseline-pdf is the right layer but is pre-1.0 with API changes expected and drags in PDF-import dependencies. The required surface is genuinely small: no encryption, annotations, forms, transparency, shading, ICC, or tagging. Owning it also removes Risk R3 for the byte-critical layer, where NFR1 needs control of every emitted byte. Cost accepted against Risk R5 (solo capacity).
- (decision) Paradigm: FUNCTIONAL CORE, IMPERATIVE SHELL, with the core as a staged immutable pipeline (Template -> Bound -> PageModel -> bytes). Names FR43's purity as the structural rule rather than a discipline, and makes the determinism boundary a directory boundary that lint can enforce.
- (decision) Canonical layout unit: int64 MILLIPOINTS (1/1000 pt), one geom package importing nothing. Makes NFR1.b structural — PDF numbers are emitted by integer-to-decimal string formatting at exactly 3 places, so no float formatter ever reaches the output stream and no float ever enters layout.
- (decision) Font data is NEVER embedded in the engine core; the engine takes an explicit FontSet value. Prevents the divergence where the native build's go:embed bytes and the browser's fetched font assets differ, producing different subsets and different hashes. Single source of truth at fonts/; the designer build copies from it.
- (decision) Designer document ownership: the Go/wasm engine OWNS the template document; TypeScript holds an immutable snapshot and dispatches committed mutations as commands. Structurally prevents the .folio schema being implemented twice (Go parser + TS model) and drifting. Also makes S5's round-trip guarantee true by construction, since Go serializes what Go will render.
- (decision) One wasm module, ONE instance, in one dedicated Worker. Rejected the two-instance (authoring + render) split despite its cleaner concurrency: it doubles resident font memory (~36MB CJK) and the concurrency benefit is bought more cheaply by having the render entry point consume SERIALIZED .folio bytes. Two workers recorded under Deferred as the escalation if render latency measurably hurts.
