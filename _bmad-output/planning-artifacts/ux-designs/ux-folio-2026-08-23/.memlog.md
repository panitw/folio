- (decision) Visual register: PRECISION INSTRUMENT — dense, technical, for professionals. Small type, tight spacing, monospace where it helps, muted chrome so the report canvas is the only bright surface. Reference class: Figma, Linear, a DAW. Rewards expertise over first impressions.
- (decision) Surfaces to design (all four): designer canvas · PDF preview mode · table structure editor (FR10) · data binding panel (FR7/FR9).
- (decision) First load: an HONEST LOADING SCREEN stating what is loading (rendering engine + fonts, once only) with progress — sets expectation rather than hiding the ~9MB, and explains why it never recurs.
- (decision) Exploration depth: ONE direction developed properly across all four surfaces, not three to compare. Register is a conviction, not a leaning.
- (decision) Handoff producer: Claude Design (in-session), overriding the default Google Stitch entry in design_handoffs. EXPERIENCE.md written first; DESIGN.md distilled from returned design work rather than authored upfront.
- (event) Sources confirmed: prd.md and addendum.md from prd-folio-2026-08-22 (both status:final). Inherited by reference, not duplicated into the spines.
- (decision) Theme: DARK CHROME, LIGHT CANVAS — single theme, not a dual system. Dark UI surrounds the white A4 page so the artefact is the only bright surface. Consistent with precision-instrument register and halves DESIGN.md token work.
- (decision) Voice: TERSE AND TECHNICAL. States the fact, names the location, offers no comfort. e.g. 'No binding for transactions[].amount'. Trusts the reader; consistent with the register.
- (decision) Input model: MOUSE-FIRST with shortcuts for common actions. Direct manipulation is primary — it is a visual canvas. No full command palette in MVP.
- (assumption) Single-theme choice means the accessibility floor cannot lean on a light-mode fallback for contrast; dark chrome must meet contrast ratios on its own terms.
- (event) EXPERIENCE.md drafted: 5 surfaces (Load, Workspace, Binding Panel, Table Editor, Preview), 10 state patterns, 6 component patterns, 2 key flows, invented section 'Determinism in the Interface', 5 open questions UX1-UX5.
- (decision) Invented EXPERIENCE.md section 'Determinism in the Interface' — NFR1's byte-identity claim creates interface obligations (canvas-approximate vs preview-exact asymmetry, never present stale preview as production, no visual language of remote processing) that no standard UX vocabulary covers.
- (decision) Band drop-targeting flagged as the most consequential ambiguity on the canvas: which band a component lands in determines whether it repeats on every page, so an ambiguous boundary produces wrong output rather than a cosmetic error.
- (decision) Added S1 load screen artboard before distilling DESIGN.md, so the token file is written once from all five surfaces. Load screen is the one place the UI is deliberately not dense — it introduces the progress-bar and manifest-row components and the only display-size type token.
- (decision) Load screen itemises the payload with real sizes (engine 1.5MB, Latin 0.4, Thai 0.1, CJK 7.4, Thai dictionary 0.12 = 9.5MB total) and states why CJK dominates. Turns dead time into an explanation of the product model rather than hiding it.

- (event) DESIGN.md distilled from all 5 artboards: 60 colour tokens, 13 type roles, zero-radius shape rule, 15 component specs, do/don't list. Two-accent grammar documented — cyan means structure, amber means data.
- (decision) Promoted all 5 artboards from .working/ to mockups/ — each anchors a decision a future reader of the spines would want to see. Seeded canvas file stays in .working/ (build output, not reference).
