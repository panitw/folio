- (direction) User: static code-legend table at content-band bottom is overdrawn by growing transactions[] table (KKP statement screenshots, design + 2-page preview). Wants a section-break line above the static table; if the dynamic table crosses the line, everything below it moves to the next page at the same position.
- (decision) Slug section-break (user choice). Input rich enough with codebase context; ambiguities resolved by direct questions instead of guided walk.
- (note) Brownfield: engine never displaces an element because a neighbour grew (AD-24); an element starting a window is drawn at page top (gap collapse); only existing push is table minHeight ElementPush; no page-break key exists; single renderer (Go engine, wasm in designer).
- (decision) Rows may use the full page below the line on pages where the below-line section does not land; the line reserves space only on the page the section lands (user choice).
- (decision) One section break per content band (user choice); several chained breaks deferred.
- (decision) The break is a designer-only marker, never drawn in the PDF; printed rules stay Line elements (user choice).
- (capability) CAP-1: author adds, moves and removes the single content-band section break on the canvas.
- (capability) CAP-2: below-line section lands on the page where above-line content ends, if it ends at or above the line; otherwise on a new following page; at declared positions either way.
- (capability) CAP-3: a break that is never crossed changes nothing in output.
- (capability) CAP-4: page count, Page X of Y, header and footer account for the page the section lands on.
- (capability) CAP-5: break persists in .folio, round-trips, is documented, invalid placement is a located load error.
- (capability) CAP-6: canvas shows the break and the below-line section from the engine projection, consistent with the PDF.
- (constraint) Deliberate, narrow exception to AD-24 and to window gap-collapse: only the below-line section moves, as a rigid block, only vertically, keeping declared y; must be written into folio-format.md Pagination.
- (constraint) Optional new key => MINOR format bump (current 4.0 -> 4.1); documents without a break keep their version and bytes.
- (constraint) Byte identity across four targets, integer fixed-point, engine is layout authority, golden fixture in hash matrix, diagnostics registered.
- (assumption) Section membership by declared top edge: element with y >= break y is below the line, regardless of x (full width).
- (assumption) Above-line content end = bottom of last above-line item on its final page, table minHeight floor included.
- (assumption) A keepTogether group with members on both sides of the line is a load error naming the group.
- (assumption) Break stored as an optional content-band key holding a y offset in points; exact key name left to implementation.
- (question) When the below-line section itself outgrows the band (e.g. contains a growing table), does it paginate under existing rules from its landing page? Assumed yes.
- (question) Does the designer draw a pushed-section echo on the page seam, or only the declared-position home? Canvas has no data, so page count is a minimum.

- (direction) User: no element may sit on both sides of the section break line; the setting is named Section Break.
- (decision) No element may straddle the break (top above, bottom below). Supersedes top-edge membership assumption: membership is unambiguous. A file with a straddler is a registered load error naming element and band; a designer move, resize or break drag that would create one is refused and leaves the document unchanged.
- (decision) Setting named Section Break in the designer; .folio key sectionBreak, following the camelCase convention of keepTogether and minHeight. Supersedes key-name-left-to-implementation assumption.
- (event) Spec re-derived after straddle and naming decisions. Self-validate pass 1 and pass 2: PASS.
- (decision) Confirmed by user: a table's minHeight floor counts toward where above-line content ends. Assumption promoted to constraint.

- (decision) CAP-1 flow (owner, story 2 planning): the Section Break behaves like an element in the designer. - (decision) Once placed (owner): click to select (its own selection, never a component), Delete or Backspace removes it, a Y field in Properties (typed value unsnapped), drag plus arrow nudge (1pt, Shift 10pt, Escape aborts). Each gesture is one engine command and one undo entry.
