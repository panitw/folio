- (direction) User: add and delete pages from the canvas toolbar above the page (not the app-shell bar) to build multi-page layouts such as legal contracts; elements are placed on a specific page; header/footer elements show on every page and stay in sync when edited.
- (decision) Slug multi-pages (user choice). Input plus codebase context rich enough; forks resolved by direct questions, not a guided walk.
- (note) Brownfield: one page setup and one content column today; canvas sheets are engine-projected windows onto that column (contentWindowOrigins), not authored pages; a page cannot be selected; header/footer already repeat on every output page and are single-source, only one canvas copy is clickable; section break is one per document; undo is engine snapshots, one command = one entry.
- (decision) Each designed page starts a new output page after the previous designed page and all its overflow pages end (user choice); a separate Page Break feature is deferred to later work.
- (decision) Delete Page removes the page and all its elements as one undo entry; the last remaining page cannot be deleted (user choice).
- (decision) Section Break becomes one per designed page, scoped to that page's content and its overflow (user choice).
