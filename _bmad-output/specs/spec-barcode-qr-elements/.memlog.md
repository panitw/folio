updated: 2026-09-13T18:16

- (direction) User asked for two new elements: Bar Code and QR Code. Mode: express (user choice).
- (decision) Slug barcode-qr-elements.
- (decision) 1D symbology scope: only the barcode used for Thai bill payment at ATMs/counters — Code 128 per Bank of Thailand/TBA standard (web-verified; max 62 chars, min height 1 cm).
- (decision) Content is a bindable string like a text element value: static text or {{ expr }} bindings (user choice).
- (decision) Scope conflict: PRD §5.3 and spec-folio SPEC list barcode/QR as out of scope; user chose spec now, sync sources after. This spec supersedes those lines.
- (constraint) Adding barcode and qrcode to the closed element-type set is a MAJOR format change (D-1.4.12/13); only documents carrying them declare the new version.
- (constraint) Codes drawn with existing PDF filled-rectangle primitive; no third-party PDF writer (AD-3), no raster image of the code.
- (constraint) Encoders pure Go, no cgo, no floats, byte-identical across four targets (AD-21); new Go module must pass licence graph (AD-26) and gomod pin test.
- (constraint) Content binds through the text-value expression evaluator; no second binding path.
- (constraint) Each element ships a golden fixture; new diagnostics registered and located by element id; designer preview comes from wasm engine.
- (capability) CAP-1 barcode element renders bound content as Code 128.
- (capability) CAP-2 qrcode element renders bound content as QR Code at authorable error-correction level.
- (capability) CAP-3 codes fit their box with quiet zone, uniform whole-millipoint modules, never distorted.
- (capability) CAP-4 unencodable, oversized, or too-small content yields located diagnostic and nothing drawn.
- (capability) CAP-5 designer places, configures and previews both elements with the real code on canvas.
- (capability) CAP-6 elements persist in .folio, round-trip byte-identically; folio-format.md documents them.
- (decision) Non-goals: other 1D/2D symbologies, Thai QR/PromptPay payload builder and CRC16 function, rotation/colours/logos/inversion, payment-semantics validation.
- (decision) Companions: symbologies.md (encoder rules, Thai payload shapes) spec-authored; spec-folio/folio-format.md adopted.
- (assumption) QR error-correction level authorable L/M/Q/H defaulting to M; version and mask chosen automatically per ISO/IEC 18004.
- (assumption) Content resolving to null hides the element silently, matching visibleIf; absent path is a located Error.
- (assumption) Thai bill-payment payload layout recalled, not verified against TBA document.
- (question) How does an author put CR separators into a bound Code 128 value — string escape or function in the expression language?
- (question) Should the barcode print human-readable text beneath the bars, on by default?
- (question) Is the QR error-correction level authorable or fixed at M?
- (question) What minimum module width triggers the too-small diagnostic?
- (event) Self-validate pass 1 (coherence): PASS — 6 caps each with intent+success, constraints each rule out options, 4 non-goals, testable success signal, IDs unique.
- (event) Self-validate pass 2 (preservation): PASS — both elements, Thai ATM symbology, bindable content, scope-supersession choice all landed; no wrapper-only content.
- (direction) User: control-character separators authored as backslash escapes (\n) in content; resolves CR question. Expression string literals reject escapes, so escapes live in the static JSON part of the value, outside {{ }}.
- (note) Thai TBA bill payment uses CR (0x0D) separators, not LF — raised to user; escape set must cover \r.
- (direction) User: no human-readable text on barcode; authors add their own text element. Resolves human-readable question; becomes a non-goal.
- (decision) Escapes \n and \r each produce exactly the byte named; no silent LF-to-CR conversion; Thai bill-payment fixture uses \r.
- (decision) QR error-correction level authorable as dropdown L/M/Q/H, default M; supersedes the ECC assumption and resolves the ECC question.
- (decision) Minimum module: 0.25 mm barcode, 0.5 mm QR. Below minimum: draw and emit located Warning (-strict fails). Cannot fit at all: located Error, nothing drawn. Resolves min-size question; CAP-4 revised.

- (event) Self-validate pass 2 (preservation) after update: PASS — separator, no-label, ECC and min-size answers all landed in SPEC.md or symbologies.md.
